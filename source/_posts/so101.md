# 从 reBot 到 SO-101：机械臂逆运动学、视觉抓取、标定工程与分布式部署

这是一篇开发心路。把 reBot 机械臂上的视觉抓取迁到 SO-101，一路经历了逆运动学、视觉抓取、标定和分布式部署。下面记下当时真正卡住的地方，以及最后是怎么走出来的。

## 缘起

大约 25 年 11 月，实验室开始讨论小车的下一步。我们实验室本身并不是做机械臂的，而是做无人系统的（无人车、无人机、无人艇等等），机械臂这一块，当时还是空白。然而，"在小车上集成一台机械臂"这个想法，从被提出那天起，至少在我心里，它就是一座小小的圣杯。Rover with manipulator，一旦做成，我们可以用它实现更多的理想，它也能去满足更广泛、也更难满足的需求。

到 26 年 5 月，我已经把机械臂开发的理论基础过了一遍，组装了 SO-101 机械臂，也在 GitHub 上 clone 了几个仓库。可直到 26 年 8 月，我都没有找到一套真正意义上、能用在 SO-101 上的视觉抓取方案。

reBot 倒是有一套完整的抓取 demo。26 年 7 月，实验室另一个兄弟团队基于 reBot B601 开发相关功能。但对我们的小车来说，B601 太重了，供电、承重都承受不起。于是任务变成：把 reBot B601 的抓取流水线，移植到 SO-101 上。

## 第一关：五自由度机械臂的逆运动学（IK）

> 一个反直觉的事实是：想让 SO-101 末端到达"某个位置 + 某个朝向"，大多数时候是做不到的。

SO-101 便宜、开源，可它和 B601 之间隔着一道很大的鸿沟：少了一个自由度。机器人位姿里，位置占 3 个自由度（前后、左右、上下），朝向又占 3 个（绕三个轴转），一共 6 个；我们只有 5 个电机。少一维，解就很难出。

权衡之下，去掉了最后一个姿态维度（roll）。真正必须对齐的，只剩两样：

- 抓手末端到达目标位置；
- 抓手的"接近方向"对准物体。

在 helpful AI assist 的辅助下，我把 IK 改成了两段式：先只解位置，再以位置解为初值，去对齐接近轴。衡量"方向对不对"，用的是点积损失：

```python
approach = T_solution[:3, :3] @ [1, 0, 0]   # 当前抓手的接近方向
axis_err = 1.0 - dot(approach, target_axis) # 0 表示完全对齐
```



## 整体的管线：从像素到夹爪

整体的管线是非常经典的视觉抓取，这次开发直接复用了 B601 的那一套。

```
像素 (u,v)
  │ 深度相机 + 内参 K
  ▼
相机坐标系
  │ 手眼矩阵 T_cam2gripper
  ▼
末端坐标系
  │ 正运动学 FK
  ▼
底座坐标系
  │ 逆运动学 IK
  ▼
关节角度 → 舵机
```

我们用"相机到物体的接近方向"和"OBB 短边的张开方向"定两根轴，再用叉积凑出第三根，组成夹爪完整的抓取姿态：

```python
approach = normalize(-position)          # 相机 → 物体的方向
open_axis = 短边在 3D 里的方向
grip_axis = cross(open_axis, approach)   # 叉积凑出右手坐标系
```

> 机器人学原理可参阅《机器人学导论》。视觉抓取原理可参阅 [这篇笔记](https://blog.csdn.net/2403_87969572/article/details/155994460)。



## 手眼矩阵 T_cam2gripper 标定

整套管线的运转，还有一个很大的技术挑战：SO-101 手眼矩阵的标定。我们需要测出属于自己这套机械臂系统的手眼矩阵。

> 手眼标定（TSAI）本质是解方程：给很多组"末端位姿 + 标记在相机里的位姿"，反推"相机相对抓手"的固定变换。如果这些位姿都长得差不多，方程就是病态的。因此，标定位姿的关节多样性至关重要。

第一次手工确定标定位姿，结果不及预期，机械臂抓取偏差极大。后来试过两次自动生成标定位姿，结果愈发离谱。

最后一次，我们生成了上百个位姿，让 IK 按照"关节 1 左/右、关节 5 大角度/小角度"去配到两个 25/25，最后再随机打乱顺序。这才完成了手眼标定。

还有一些小巧思：

1. 机械臂URDF模型文件的"0 度"和舵机的"0 度"也需要对齐。这一点其实比较容易想到，可如果没想到，就会卡很久。
2. 我们还需要知道相机光轴在抓手坐标系里到底朝向哪个轴。后来写了一个脚本，把 ±X、±Y、±Z 六个候选方向都试了一遍。



## 分布式部署

我们把相关逻辑接入 ROS 并分布式部署。PC 做人机交互——看画面、按按键，其他功能放在小车 Jetson 上，二者协同运行。

漫漫长夜迎来曙光。屏幕上出现机械臂视角的画面和物体检测框，按下键盘，远处的机械臂按预期完成了抓取。

> Tip：PC 是 x86，Jetson 是 ARM。Python 虚拟环境并不兼容。



## 写在最后

这次开发不是一帆风顺的。客观条件也有不少制约。可我们还是想千法、舍万法地把它做出来了——或许这就是这个项目让我印象最深的地方。当然，过程里也有很多主动的妥协。

还有一点感触。到了最后比赛，其实真的不是在炫技，而是大家——至少在相互答辩的环节——真的比较关心这个产品有没有用、能不能落地。这一点，感觉也是明年学弟学妹们继续努力的方向吧。
