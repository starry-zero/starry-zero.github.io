这是一篇开发心路。把 reBot 机械臂上的视觉抓取迁到 SO-101，一路经历了逆运动学、视觉抓取、标定和分布式部署。下面记下当时真正卡住的地方，以及最后是怎么走出来的。

## 缘起

大约 25 年 11 月，实验室开始讨论小车的下一步。「Rover with manipulator」这个想法被提出。在当时的队员心里，这就是了一座小小的「圣杯」。然而我们实验室本身并不是做机械臂的，而是做无人系统的（无人车、无人机、无人艇等等），机械臂这一块，还没有相关的积淀。

到 26 年 5 月，我们已经对机械臂开发的理论基础有所了解，组装了 SO-101 机械臂，也尝试复现了几个相关的开源项目仓库。可直到 26 年 8 月，我们都没有找到一套真正意义上、能用在 SO-101 上的视觉抓取方案。

reBot 倒是有一套完整的抓取 demo。26 年 7 月，实验室另一个兄弟团队基于 reBot B601 开发相关功能。但对我们的小车来说，reBot 太重了，供电、承重都承受不起。于是任务变成：把 reBot B601 的抓取流水线，移植到 SO-101 上。

## 第一关：五自由度机械臂的逆运动学（IK）

> 一个反直觉的事实是：想让 SO-101 末端到达「某个位置 + 某个朝向」，大多数时候是做不到的。

SO-101 便宜、开源，可它和 reBot B601 之间隔着一道很大的鸿沟：少了一个自由度。机器人位姿里，位置占 3 个自由度（前后、左右、上下），朝向又占 3 个（绕三个轴转），一共 6 个；而我们只有 5 个舵机。

权衡之下，我们去掉了最后一个姿态维度（roll）。真正必须对齐的，只剩两样：

- 抓手末端到达目标位置；
- 抓手的「接近方向」对准物体。

我们把 IK 改成了两段式：先只解位置，再以位置解为初值，去对齐接近轴。衡量「方向对不对」，用的是点积损失，代码片段如下：

```python
approach = T_solution[:3, :3] @ [1, 0, 0]   # 当前抓手的接近方向
axis_err = 1.0 - dot(approach, target_axis) # 0 表示完全对齐
```



## 整体的管线：从像素到夹爪

整体的管线直接复用了 reBot B601 的那一套，流程如下：

```
像素 (u,v)
  │ 深度相机 + 内参 K
  ▼
相机坐标系
  │ 手眼矩阵 T_cam2gripper
  ▼
末端坐标系
  │ 正运动学 FK
  ▼
底座坐标系
  │ 逆运动学 IK
  ▼
关节角度 → 舵机
```

我们用「相机到物体的接近方向」和「OBB 短边的张开方向」定两根轴，再用叉积凑出第三根，组成夹爪完整的抓取姿态：

```python
approach = normalize(-position)          # 相机 → 物体的方向
open_axis = 短边在 3D 里的方向
grip_axis = cross(open_axis, approach)   # 叉积凑出右手坐标系
```


## 手眼矩阵 T_cam2gripper 标定

整套管线的运转，还有一个很大的技术挑战：SO-101 手眼矩阵的标定。我们需要测出属于自己这套机械臂系统的手眼矩阵。

> 手眼标定（TSAI）本质是解方程：给很多组「末端位姿 + 标记在相机里的位姿」，反推「相机相对抓手」的固定变换。如果这些位姿都长得差不多，方程就是病态的。因此，标定位姿的关节多样性至关重要。

第一次手工确定标定位姿，结果不及预期，机械臂抓取偏差极大。后来试过两次自动生成标定位姿，结果愈发离谱。

最后一次，我们生成了上百个位姿，让 IK 按照「关节 1 左/右、关节 5 大角度/小角度」去配到两个 25/25，最后再随机打乱顺序。这才完成了手眼标定。





## 分布式部署

我们把相关逻辑接入 ROS 并分布式部署。PC 做人机交互——看画面、按按键，其他功能放在小车 Jetson 上，二者协同运行。

**漫漫长夜迎来曙光。**
屏幕上出现机械臂视角的画面和物体检测框，按下键盘，远处的机械臂按预期完成了抓取。
